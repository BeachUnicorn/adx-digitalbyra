## Implemented helpers (call these)

### links.py (router section "S4")

```python
NAMED_SLUG_RE, NAMED_SLUG_TEXT            # [a-z0-9] then [a-z0-9-], 1 to 40, no - first or last
clean_named_slug(raw) -> "vinter"         # lower-cased; LinkRefused(NAMED_SLUG_TEXT) otherwise
named_link_url(link, public_slug=None)    # "https://klick.adx.se/exempelror/vinter"
named_link_text(link, public_slug=None)   # "klick.adx.se/exempelror/vinter" (list, Kopiera)
SNIPPET_SOURCE                            # "utskick/s.js" under static/
snippet_version() -> "1a2b3c4d"           # first 8 hex of sha256(s.js), "" without the file
snippet_body(ver) -> bytes | None         # current s.js when ver matches, else an archived
                                          # static/utskick/s.<ver>.js whose own hash is ver
snippet_integrity(ver=None) -> "sha384-..."   # SRI of exactly the served bytes
snippet_url(ver=None)                     # "https://klick.adx.se/s.1a2b3c4d.js"
beacon_url()                              # "https://klick.adx.se/v"
snippet_tag(site) -> str                  # the whole <script ... data-k="<key>" async></script>
```

The file is read once per process and re-read when its mtime or size changes. When `s.js`
changes, copy the old file to `static/utskick/s.<old version>.js` so installed tags keep
loading (their SRI hash belongs to the old bytes).

### qr.py

```python
qr.FORMATS                                # ("svg", "png")
qr.svg(data, *, scale=10) -> bytes        # width, height and viewBox; no classes, no XML declaration
qr.png(data, *, scale=10) -> bytes
qr.response(data, fmt, *, filename, download=False)   # 404 for another fmt; inline or attachment,
                                          # safe filename, Cache-Control private 1 h, nosniff
```

Always a full QR code (`segno.make_qr`, never Micro QR), error level M, quiet zone 4.

### The seams between builders

- **Follow-up (B calls A)**: `utskick_follow_up` calls `segments.create_follow_up(utskick,
  user=request.user)` (rules "got_utskick in [pk]" AND "clicked not_in [pk]", name "Klickade
  inte: <namn>") and then goes on: to the segment page, or to a new draft utskick whose
  audience is `{"segments": [segment.pk]}` (decide together; a new draft goes through
  `app_utskick_new`'s rules for `channel_mode` and the sender).
- **Segments in the audience (A)**: once `audience.clean` accepts segment ids, `app_utskick_count`,
  Granska and the freeze count segments with no other change (they all go through
  `audience.contacts`). `confirm_summary` keeps the numbers as today.
- **The contact card is shared by A and B**: `app_views/contacts.py` `contact_detail` and
  `kontakter/detail.html`: A adds `segment_chips` (Listor och taggar card), B adds
  `reply_habit` (Sammanfattning), `sms_problem` and the "Skicka sms" button and form. Two
  marked blocks each, no shared lines.
- **Site visits (C writes, A and B read)**: `snippet_beacon` writes
  `Event(kind="site_visit", contact=click.contact, utskick=click.utskick,
  recipient=click.recipient, data={"klick": click.pk, "sida": <path, at most 80 chars, no
  query>, "varde": <Origin host>})` once per click and 30 minutes (only when the click has a
  contact), and updates the click like `attribution.record_beacon` (engaged seconds, scanner
  upgraded to human) plus `lp_visits` and `first_visit_at` (the visit count on the destination,
  as for a landing page). The timeline (B) shows "Besökte webbplatsen" with the page; the rule
  `visited_lp` (A) reads both `lp_visit` and `site_visit`; the report's LP behaviour (B) reads
  only clicks on links of kind `lp`.
- **Direct threads (B)**: `threads._new_thread` creates the thread's Inkorg lead with status
  `new`; a contact-card sms must not raise the badge, so create the direct thread's lead as
  `contacted` ("Klar") and let a reply make it new again (`add_inbound` does). The reply finds
  the thread through the sms (`thread_for`, `ThreadMessage.sms_message`).
- **Named links in the report (C, B)**: named links have no utskick, so they never show in an
  utskick report; their numbers live on the link (`human_clicks`, `leads` through `rollup`) and
  on `link_detail`.

  --noinput` (`--parallel 1` for the full suite). No network.

  `HTTP_HOST="klick.adx.se"`; POSTs with `Client(enforce_csrf_checks=True)`; assert that no
  response sets a cookie. The snippet file helpers read `settings.BASE_DIR / "static"`, so
  `override_settings(BASE_DIR=<tmp>)` gives a test its own `s.js` (`SnippetFileTests`).
- Utskick tests use `testing.UtskickFixture`; `make_named` in `test_s4_foundation` shows the
  minimum named link.
- Guards that bite in S4: no `style=` and no inline `<script>` under `templates/flamingo/app/`
  (the server-rendered chart SVG takes its size from CSS, not a `style=`), `data-label` on every
  `<td` (the guard matches the literal text, comments included), every CSS and JS file a
  template loads must be in static_version (done for the names above; a new name needs the
  lead), copy rules everywhere incl. `test_*.py` (no en or em dash, typographic quotes, ellipsis
  character, `[ ]` decoration, exclamation marks in copy, response-time promises; write
  `chr(0x2013)` in tests), the snippet guard (no `cookie`, `localStorage`, `sessionStorage`,
  `indexedDB` or `caches.` in `static/utskick/s*.js`, under 2 kB).
- Tenancy (H.1): every id from a path through `owned`, every id from a body or JSON through

## Deviations from the contract (foundation)

1. **Named links keep `kind` lp or external.** B.2 lists `named` as a `TrackedLink.kind`, but
   every existing rule keys on the kind: `destination_ok` re-checks only `external` (a `named`
   kind would skip the E.8 host check at every click), and `build_destination` and
   `bare_destination` add `ut` and the anchor only for `lp`. A named link is therefore `utskick
   IS NULL` plus a slug (`TrackedLink.is_named`), with the destination's kind; `Kind.NAMED` is
   never written (the choice stays, so no migration). Clicks on named links use
   `Click.Channel.NAMED`. The check `utskick_link_named_slug` keeps a link without utskick from
   having no address.
2. **Snippet domains do not make links free from review.** E.8 lists "its snippet domains"
   among the hosts allowed without review, and `links.own_domains` already read `SiteSnippet`.
   But the customer types the domain, and the beacon that sets `last_seen_at` can be sent by
   any client with any `Origin` and a click token the customer gets by clicking their own link,
   so a snippet domain proves nothing. `own_domains` now reads only `Customer.website` and
   verified sender domains (the `SiteSnippet` branch was dead code until 0004, so nothing that
   ran before changes). The same holds for information utskick (H.5 "the customer's own site",
   `checks.own_hosts` is `own_domains`). The snippet page requests a domain that is not already
   allowed from ADX (`links.request_host`), and the script works on it either way. Lead:
   confirm with Giovanni.
3. **Reserved public slugs**: `a`, `b`, `c`, `m`, `o`, `p`, `s`, `v`, `w` join
   `RESERVED_PUBLIC_SLUGS`, so `klick.adx.se/<public_slug>/<slug>` can never collide with the
   link hosts' own paths. And a slug may not start with `mcp`, `authorize`, `token`,
   `register` or `revoke` (`RESERVED_PUBLIC_SLUG_PREFIXES`, `access.is_reserved_slug`): nginx
   (`server/lib.sh`, the link block's `location ~ ^/(mcp|authorize|token|register|revoke|...)`)
   and `asgi_app._is_oauth_path` answer 404 for every path that merely starts with those words,
   so `klick.adx.se/tokenbolaget/vinter` would never reach the app. `suggest_public_slug` puts
   `kund-` in front of such a name ("kund-tokenbolaget"). Lead: check production before deploy
   (`UtskickSettings` rows whose `public_slug` is one of the letters or starts with one of the
   prefixes; expected none). A tighter nginx and ASGI match (`(/|$)` after the word) would
   lift the prefix rule, but changes the MCP routing on adx.se; not done.
4. **The account part of a named link allows `_`** (`[a-z0-9_-]{1,40}`, E.1 says `[a-z0-9-]+`):
   `access.validate_public_slug` accepts underscores. The slug part is `[a-z0-9-]{1,40}`
   (`links.NAMED_SLUG_RE`).
5. **`app_segment_count` is `kontakter/segment/antal/` without a pk**, POST with the rules as
   JSON: the count runs while a new, unsaved segment is edited (I.1 shows `.../antal/` under the
   segment).
6. **An extra route `app_link`** (`utskick/lankar/<pk>/`) gives the "Rapport" action of a named
   link (I.11) a page; I.1 lists only the list, the form and the QR codes.
7. **New modules for one owner each**: the follow-up and export views are in
   `app_views/report.py` (the report itself stays in `app_views/utskick.py`), the contact-card
   sms view in `app_views/contact_sms.py` and its rules in `contact_sms.py`, and the signup QR
   view in `app_views/links.py` (the QR builder owns QR).
8. **QR routes carry the format**: `app_link_qr` takes `[pk, "svg" | "png"]`, `app_signup_qr`
   takes `["svg" | "png"]` (one name per route, as I.1 has it); any other extension is 404.
9. **Old snippet versions keep loading** from `static/utskick/s.<ver>.js` when their own hash is
   that version (E.6 does not say what happens to installed tags when the script changes).
10. **No new settings in S4.** The `adx` parameter carries `tokens.ut_token(click.pk)`, the same
    token as `ut` (E.3 and E.6 leave the format open; the beacon reads it with `tokens.read_ut`).
11. **The stub templates are back** (S3's integration had removed them and the guard in
    `test_s2_ui`); see the table above for when they go.

  sets it, so the first visit comes from a test link on the Spårningsskript page:
  `https://<domän>/?adx=<install token>` (`site_snippet.install_token`, the shape of `ut`
